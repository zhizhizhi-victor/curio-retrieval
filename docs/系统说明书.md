# Curio 系统说明书

**系统全称：** Curio · Attribute-Compositional Chinese Museum Retrieval  
**任务类型：** 领域特定文字到图像检索（Domain-Specific Text-to-Image Retrieval）  
**课程：** COMP5523 Computer Vision and Image Processing  
**仓库：** https://github.com/zhizhizhi-victor/curio-retrieval  
**文档版本：** 2026-11-01  

---

## 1. 系统是做什么的

Curio 接收一句自然语言描述（英文或中文属性词），在**固定的中国博物馆馆藏图库**中检索，并返回按相关程度排序的图片列表。

| 部分 | 含义 |
|---|---|
| **Query** | 用户输入，如 `Qing porcelain vase` / `清代瓷瓶` |
| **Gallery** | 本地固定图库（1052 张开放获取馆藏图） |
| **Ranked results** | 按相关度排序的结果，并附带属性匹配证据 |

**不是**通用搜图引擎，也**不是**大规模图像微调系统；重点是：多属性约束（时期 × 材质 × 器型）如何进入排序，以及结果是否可解释。

---

## 2. 相关性如何定义

### 2.1 严格相关（主指标 mAP / P@K 使用）

从查询中解析出约束集合 \(C \subseteq \{\text{period}, \text{material}, \text{object\_type}\}\)。  
图库条目 \(i\) **严格相关**，当且仅当对每个已声明约束 \(c \in C\)，都有 \(i[c] = C[c]\)。

| 查询 | 完整相关 | 不算完整相关 |
|---|---|---|
| Qing porcelain vase | 清代瓷瓶 | 清代玉瓶；明代瓷瓶；清代瓷碗 |
| 清代瓷瓶 | 同上（中文词表解析） | 同上 |

### 2.2 分级相关（nDCG@10 使用）

命中已声明约束的比例 ∈ [0, 1]。部分匹配也会获得部分增益，用于衡量“排在前面的结果有多贴边”。

### 2.3 界面证据（Evidence）

每条结果展示 period / material / object_type 的：

- **match**：与查询解析结果一致  
- **conflict**：查询要求了但图库字段不一致  
- **unspecified**：查询未提及该维

## 4. 模型与算法（重要：几乎不做“训练”）

### 4.1 先说清楚：本系统有没有训练？

| 项目 | 是否做了 |
|---|---|
| 从零训练视觉大模型 | **否** |
| CLIP / SigLIP 全量微调、LoRA | **否** |
| 使用公开预训练 CLIP 做零样本检索 | **是** |
| 属性词表、多提示融合、软门控超参 | **是**（规则 + 验证集选 β） |
| 离线图像向量索引 | **是**（编码一次存盘，不是“训练权重”） |

因此报告里说的“效果”，主要是**检索排序实验效果**，不是“模型训练曲线 / loss 下降”。

### 4.2 使用的模型

| 组件 | 选型 |
|---|---|
| 视觉—语言模型 | **OpenAI CLIP ViT-B/32**（`openai/clip-vit-base-patch32`） |
| 图像编码维度 | 512 维，L2 归一化 |
| 图像索引文件 | `data/index.npz`（随仓库提供，可重建） |
| 权重获取 | 首次运行从 Hugging Face 自动下载；大权重不进 git |
| 元数据基线 | **BM25Okapi**（`rank-bm25`） |

### 4.3 五种检索方法

#### A. BM25（元数据关键词基线）

把 title、材质、器型、时期等拼成英文文档，对查询做关键词排序。不看像素。

#### B. CLIP（纯视觉—语言）

查询编码为文本向量，与全库图像向量做余弦相似度排序。

#### C. CLIP + 属性重排（clip_rerank）

1. CLIP 取 Top-100 候选  
2. 解析查询属性  
3. \(\text{score} = \cos(q,i) + \alpha \cdot \text{attr\_score}(i)\)  
4. \(\alpha\) 在验证集上搜索；本轮选定 **α = 0.1**

#### D. Compositional CLIP（旗舰方法）

本系统核心贡献：

1. 解析 period / material / object_type  
2. 构造多条提示（原句 + 各属性专用英文提示）  
3. 各通道分别与图像做 CLIP 相似度，再加权融合  
4. 软属性门控：\(\text{score}' = \text{score} \cdot (1 + \beta \cdot \text{attr\_score})\)  
5. 验证集按 nDCG@10 选 **β = 0.5**

#### E. Hybrid RRF

将 BM25 排序列表与 Compositional 列表做 Reciprocal Rank Fusion（k=60），融合元数据与视觉通道。

## 5. 实验结果（“训练/系统效果”）

### 5.1 实验设置

- Gallery：1052  
- Val：20；Test：64  
- 选定：α=0.1，gate β=0.5（val compositional nDCG@10 ≈ 0.775）  
- 指标：P@5、P@10、R@10、mAP、nDCG@10  

### 5.2 测试集结果

| Method | P@5 | P@10 | R@10 | mAP | nDCG@10 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.5594 | 0.4719 | 0.5032 | 0.6617 | 0.6986 |
| CLIP | 0.1750 | 0.1625 | 0.0899 | 0.1411 | 0.3151 |
| CLIP + rerank | 0.4688 | 0.3656 | 0.2905 | 0.3791 | 0.6740 |
| **Compositional（主方法）** | **0.6469** | **0.5500** | **0.5807** | **0.8149** | 0.8551 |
| Hybrid RRF | 0.6594 | 0.5734 | 0.5641 | 0.7834 | **0.8748** |

完整机器可读结果：`results/evaluation.json`、`results/metrics.csv`、`results/experiment_report.md`。

### 5.3 效果解读

1. **纯 CLIP 偏弱**：对朝代/材质等硬约束不稳定。  
2. **属性重排有提升**，但仍明显低于组合式方法。  
3. **Compositional 在 mAP 上最好（0.81）**，说明多提示分解 + 门控有效。  
4. **Hybrid 在 nDCG 上略高（0.87）**，元数据与视觉可互补。  
5. **诚实边界：** 评价标签来自元数据；属性方法与 GT 同源，会抬高属性类方法。演示时应结合 evidence 与失败案例说明。

### 5.4 没有“训练曲线”时怎么讲成果

可汇报为：

> 我们在固定中国馆藏图库上完成了可复现的检索实验。未做 CLIP 微调；通过属性组合式多提示与软门控，将测试集 mAP 从纯 CLIP 的 0.14 提升到 0.81，并超过元数据 BM25 基线（0.66）。

## 6. 系统架构与文件说明

```text
curio-retrieval/
  app.py                      # Flask Web 服务与 API
  static/                     # 前端（Search / Experiments / About）
  retrieval/
    engine.py                 # 五种方法调度
    compositional.py          # 多提示融合 / soft gate / evidence / RRF
    attributes.py             # 中英属性词表与解析
    clip_retriever.py         # CLIP 检索
    bm25_retriever.py         # BM25
    metrics.py                # P@K / AP / nDCG
  scripts/
    sync_gallery_from_disk.py # 从图重建 gallery.json
    build_index.py            # 重建 CLIP 图像索引
    make_benchmark.py         # 生成评价查询
    evaluate.py               # 跑实验出表
  data/
    gallery.json              # 图库元数据
    images/                   # 本地图片
    index.npz                 # CLIP 图像向量
    queries.json              # val/test 查询
  results/                    # 评价指标输出
  docs/                       # 本说明书与报告
```

### 主要 API

| 接口 | 作用 |
|---|---|
| `GET /` | Web 界面 |
| `GET /api/health` | 图库规模、版本 |
| `GET /api/facets` | 材质/器型/时期筛选项 |
| `POST /api/search` | 检索；默认 method=`compositional` |
| `GET /api/metrics` | 实验结果 JSON |
| `GET /api/queries` | 评价查询列表 |

## 7. 安装与使用说明

### 7.1 环境要求

- Python 3.10+ 推荐  
- 依赖见 `requirements.txt`（Flask、PyTorch、transformers、rank-bm25、Pillow 等）  
- 首次加载 CLIP 需要能访问 Hugging Face  

### 7.2 快速启动（组员）

```bash
git clone https://github.com/zhizhizhi-victor/curio-retrieval.git
cd curio-retrieval
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py --port 8765 --preload
```

浏览器打开：**http://127.0.0.1:8765**

### 7.3 界面怎么用

1. **Search**  
   - 输入查询（如 `Qing porcelain vase` 或 `清代瓷瓶`）  
   - 方法默认 **Compositional CLIP**  
   - 可切换 Hybrid / Rerank / CLIP / BM25  
   - 可用 Material / Object / Period 二次过滤  
   - 结果含排序分与 match/conflict 标签；点击可放大  

2. **Experiments**  
   - 查看各方法 P@K / mAP / nDCG  
   - 选择测试查询一键回放到 Search  

3. **About**  
   - 任务、相关标准、方法与数据摘要  

### 7.4 可选：重建索引与复现实验

```bash
python scripts/sync_gallery_from_disk.py
python scripts/build_index.py
python scripts/make_benchmark.py
python scripts/evaluate.py
```

## 9. 局限与后续可改进

1. 相关标签为元数据弱标签，存在噪声与同源偏差。  
2. 纹饰、釉色等细粒度外观未进入硬相关定义。  
3. 未做领域微调；更强 backbone / 轻量适配或可继续提升。  
4. AIC 等来源因网络未完整并入。  
5. 中文查询目前走属性词表解析，CLIP 提示仍以英文模板为主。
