## 开场（约 30 秒）

大家好，我汇报的系统叫 **Curio**，做的是课程要求的 **Domain-Specific Text-to-Image Retrieval**。

一句话概括任务：

> 用户输入一句自然语言（Query）→ 在固定的中国博物馆馆藏图库（Gallery）里检索 → 返回按相关程度排序的图片（Ranked results）。

领域选的是 **中国博物馆馆藏器物**（陶瓷、玉器、青铜等），不是通用 ImageNet、也不是服装检索。

---

## 一、设计思路（约 1.5 分钟）

### 1. 什么叫“相关”

我们不把“看起来像文物”就算相关，而是按课程强调的多条件相关来定义：

查询里如果提到了 **时期、材质、器型**，相关图片必须同时满足这些条件。

例如查询 `Qing porcelain vase`：

- 清代瓷瓶 → 相关  
- 清代玉瓶 → 材质不对，不算完整相关  
- 明代瓷瓶 → 时期不对  
- 清代瓷碗 → 器型不对  

评价时还有两层指标：

- **严格相关**：所有约束都匹配 → 用来算 mAP、P@K  
- **分级相关**：命中一部分约束也给部分分 → 用来算 nDCG@10  

### 2. 核心设计：属性组合式检索

文物查询天然是“组合属性”的，比如“清代 + 瓷 + 瓶”。  
如果只用一个文本向量去对全库，CLIP 往往能抓住大概外观，但对朝代、材质这种硬约束不稳定。

所以我们的主方法不是“单句进 CLIP 排一次”，而是：

1. **解析查询属性**：从句子里抽出 period / material / object_type（支持英文和中文词表，如「清代瓷瓶」）  
2. **多提示（multi-prompt）**：除了原句，再生成属性专用提示，例如  
   - “a Chinese museum artifact from the Qing dynasty”  
   - “a Chinese porcelain artifact photograph”  
   - “a Chinese vase in a museum collection”  
3. **多通道打分再融合**：各提示分别和图像做 CLIP 相似度，再加权合成  
4. **软属性门控（soft gate）**：若某图属性与查询冲突则降权，匹配则升权  
5. **可解释证据（evidence）**：结果上标出 period / material / type 是 match 还是 conflict，方便讲解和查错  

另外保留两条基线方便对比：

- **BM25**：只看元数据关键词，不看图  
- **纯 CLIP**：单句视觉—语言相似度  
- **CLIP + 属性重排**：先 CLIP 取候选，再加一点属性分  

还有一个可选融合：**Hybrid RRF**（BM25 排序与组合式排序做 Reciprocal Rank Fusion）。

## 二、用的模型与技术栈（约 40 秒）

| 部分 | 选型 |
|---|---|
| 视觉—语言模型 | **OpenAI CLIP ViT-B/32**（`openai/clip-vit-base-patch32`） |
| 图像侧 | 图库离线编码成 512 维向量，存 `data/index.npz` |
| 文本侧 | 查询在线编码；组合式方法会编码多条提示 |
| 元数据基线 | **BM25Okapi** |
| 服务与界面 | Python + Flask + 前端静态页 |
| 语言 | 检索界面以英文为主，属性解析支持中英词表 |

说明：我们用的是公开预训练 CLIP，**没有做大规模图像 LoRA 微调**；重点放在“如何把多属性约束显式接进排序”。

## 三、数据集从哪里来（约 1 分钟）

### 来源

选用海外开放获取、可合法下载复现的数据：

1. **The Metropolitan Museum of Art（Met）Open Access**  
2. **Cleveland Museum of Art Open Access（CC0）**  

筛选条件：

- 文化/部门与中国相关  
- 有图片且许可为 Public Domain / CC0  
- 能规范出材质、器型、时期标签  

最终固定图库：**1052 张**（Met 约 645，Cleveland 约 407），本地保存在 `data/images/`，元数据在 `data/gallery.json`。

### 评价集

用图库元数据自动构造查询与相关集，共 **84** 条：

- 验证集 20（只用于选超参 β）  
- 测试集 64（最终报分）  

查询类型包括单属性、双/三属性组合，以及少量中文三元组（如「清代瓷瓶」）。  
相关判定：条目字段与查询约束精确匹配。  
（诚实说明：这是弱标签，正式答辩前最好人工抽查一部分。）

## 四、效果怎么样（约 1 分钟）

测试集主要数字（gallery=1052，test=64；门控 β=0.5）：

| 方法 | P@5 | mAP | nDCG@10 |
|---|---:|---:|---:|
| 纯 CLIP | 0.18 | 0.14 | 0.32 |
| CLIP + 属性重排 | 0.47 | 0.38 | 0.67 |
| BM25（元数据） | 0.56 | 0.66 | 0.70 |
| **组合式 Compositional（主方法）** | **0.65** | **0.81** | **0.86** |
| Hybrid RRF | 0.66 | 0.78 | **0.87** |

怎么讲效果：

1. **纯 CLIP 偏弱**：细粒度朝代/材质约束不好抓。  
2. **加属性重排有提升**，但仍明显低于组合式。  
3. **组合式多提示 + 门控** 在 mAP 上最好（0.81），说明把属性拆开再融合是有效的。  
4. **Hybrid** 在 nDCG 上略高，说明元数据与视觉排序可以互补。  

注意一句边界：评价标签来自元数据，属性方法会偏有利；演示时要用界面 evidence 和失败例子说明“系统到底匹配了什么”。

## 五、界面怎么操作、怎么看（演示脚本，约 2 分钟）

打开：**http://127.0.0.1:8765**  
顶部三个页签：**Search / Experiments / About**

### Search（主演示）

1. 上方输入框输入查询，例如：  
   - `Qing porcelain vase`  
   - 或中文：`清代瓷瓶`  
2. 方法下拉框默认选 **Compositional CLIP (flagship)**（主方法）。  
   可切换对比：Hybrid RRF / CLIP + rerank / CLIP only / BM25。  
3. 点 **Search**。  
4. 下方网格是排序结果：标题、时期·材质·器型、分数。  
5. 每张结果下方有彩色小标签（chips）：  
   - 绿色 **match** = 该属性对上了  
   - 红色 **conflict** = 查询要求了但图上不一致  
6. 可选左侧三个过滤器（Material / Object type / Period）做二次收窄。  
7. 点图片可放大看细节与元数据。

**建议现场对比（同一句查询切换方法）：**

- 先选 CLIP only → 看是否容易出时期/材质错的图  
- 再选 Compositional → 看 top 结果更贴约束，且 chips 多为 match  

### Experiments（看实验数字）

1. 点 **Experiments**  
2. 表格里是各方法的 P@5、P@10、R@10、mAP、nDCG@10  
3. 下方可点选测试查询，查看约束与相关图数量，再回 Search 复现  

### About

任务定义、相关标准、数据与方法的一页说明，答辩提问时可翻到这里。

总结三句话：

1. **问题：** 中国馆藏领域的文字到图片检索，相关 = 时期×材质×器型多约束。

## 附：可能被问到的简短回答

**Q：标签是看图标的吗？**  
A：不是。来自博物馆开放编目，再规则规范化；相关判定是字段精确匹配。

**Q：为什么不用更大模型？**  
A：本项目重点是多属性约束如何进入排序与解释；用公开 CLIP 即可复现对比。

**Q：中文查询怎么支持？**  
A：属性词表里有中英别名，解析出属性后再走同一套组合式提示（提示本身仍用英文模板喂 CLIP）。

**Q：BM25 为什么也不错？**  
A：查询模板和元数据用词重叠高，且标签同源；所以元数据基线强。我们用它证明“约束可被满足”，主方法则同时利用视觉通道与属性通道。
